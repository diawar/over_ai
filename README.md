# CoreLab

Платформа управления каталогом и характеристиками товаров с Mini App для подбора ПК. Организации управляют пользователями, оформлением, филиалами, складами, календарями и маршрутами. Предложения источников сопоставляются с товарами каталога.

## Запуск

Потребуется Docker Desktop. Скопируйте `corelab/.env.example` в `corelab/.env`, задайте собственные пароль PostgreSQL, `SESSION_SECRET` и начальные `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Пароль в `DATABASE_URL` должен совпадать с `POSTGRES_PASSWORD`.

Из каталога `corelab` выполните:

```sh
docker compose up -d --build
```

Сайт и админка: `http://localhost:5173/`, Mini App: `http://localhost:5173/mini-app/`. Подробности: [руководство CoreLab](corelab/README.md). Данные рабочей БД, локальные снимки товаров и ключи в репозиторий не включены. Для новой установки каталог и настройки организации нужно заполнить отдельно.

## AI-конфигуратор

Ключ и модель выбираются в настройках организации. Поддерживаются OpenAI, Kimi (включая `kimi-k3`) и OpenRouter. Платное заполнение характеристик запускается отдельно от диалога и подбора.

Новый механизм, в котором AI выбирает точные SKU, а сервер проверяет состав, остаётся экспериментальным. Пользовательский Mini App использует прежний механизм подбора; переключение провайдера диалога само по себе не включает экспериментальный планировщик. Детали и ограничения: [состояние реализации](CORELAB_IMPLEMENTATION_PLAN.md).

## Проверки

```sh
node --test tests/*.cjs
cd corelab/frontend
npm ci
npm test -- --maxWorkers=2
npm run build
```

Backend-тесты используют отдельные PostgreSQL-базы. Не направляйте `DATABASE_URL` / `TEST_DATABASE_URL` тестового процесса на рабочую базу.

Инструменты сотрудничества агентов находятся в подмодуле `.handoff`; при необходимости загрузите их через `git submodule update --init`.
