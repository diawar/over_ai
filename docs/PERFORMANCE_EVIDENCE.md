# Оценка производительности

Сборщик сопоставляет доступные комплектующие CoreLab с измерениями по точной модели и подтверждённому объёму VRAM. Название модели — ключ записи теста, а не правило допуска. Марка, серия и цена сами по себе балл производительности не дают.

Источники игровых измерений — [рейтинги GPU](https://www.computerbase.de/artikel/grafikkarten/rangliste.2487/) и [CPU](https://www.computerbase.de/artikel/prozessoren/rangliste.89909/) ComputerBase. `node tools/refresh-computerbase-benchmarks.cjs` обновляет локальный снимок. Изменения проверяются перед перезапуском Mini App; автоматическая замена тестов только в памяти сервера отключена. Админка и сборщик используют одни локальные файлы. Для нескольких CPU также сохранены ранее сверенные измерения ComputerBase на случай отсутствия записи в текущем рейтинге.

[pc-builds.com](https://pc-builds.com/ru/fps-calculator/) остаётся отдельной приблизительной оценкой только для точно сверенных сочетаний CPU, GPU, VRAM, игры, разрешения и настроек. Он не определяет рейтинг. UserBenchmark не используется.

Допуск для QHD/4K проверяет VRAM и результат соответствующего тестового набора. FPS разных тестовых систем не складываются и не выдаются за прогноз готовой сборки. Совместимость, наличие и бюджет проверяются отдельно. Отсутствие измерения не подменяется догадкой по номеру модели.

## Модели и новые товары, 2026-11-04

`tools/performance-models.json` хранит правила точной идентификации и явные алиасы моделей; `tools/benchmark-observations.json` — игровые измерения и источники. GPU сопоставляется по модели чипа и объёму VRAM; CPU — по точному обозначению с сохранением суффиксов. BOX/OEM и названия производителей видеокарт не создают отдельные оценки. Новая линейка CPU с другим именованием может быть добавлена в `models` как `type: cpu`, `name`, `manufacturer`, `aliases` без изменения сборщика. Неоднозначное обозначение остаётся неподтверждённым.

В каталоге ссылка «Оценки CPU и GPU» открывает `/admin/performance-models`. Очередь вычисляется из текущих товаров организации, включая ещё не допущенные карточки. Измерения общие, товары и их ссылки изолированы по организации. Статусы: `measured`, `not_evaluated`, `identity_missing`. Статус тестов не заменяет проверку совместимости, цены и остатков.

Для R9700 32 GB есть точная идентификация, но нет выдуманного балла. Игровые рекомендации без тестов GPU не формируются автоматически; CPU без измерений не получает балл из числа ядер. Явный выбор точного SKU допускает проверку совместимости с предупреждением, но не отменяет требования разрешения, питания и размеров. В играх приоритет измеренных CPU действует среди сборок в бюджете.

Рабочие тесты покрывают часть моделей и программ (наборы перечислены ниже). При неполном покрытии подбор остаётся предварительным по требованиям/цене с предупреждением о неподтверждённой оптимальности. Игровые FPS не используются как тест Photoshop/Twinmotion. Произвольный числовой индекс RTX/RX удалён, запрос минимального игрового уровня сопоставляется по одному набору тестов.

Обновление без платного API: проверить точную модель, VRAM, методику, источник и дату; внести измерение в соответствующий набор локального JSON; выполнить тесты моделей и сборщика; перезапустить mini_app. Не смешивать FPS разных методик и не переносить результаты между вариантами памяти без подтверждения.
# Профили задач — 2026-11-04

`partPreferences.workloadProfile` version 1 хранит программу, операцию (`interactive`,
`cpu_render`, `gpu_render`), приоритет и сложность. ИИ заполняет профиль по ответам
клиента; сервер валидирует, сохраняет его в текущей сессии и замораживает на стадии
review. Смешанная задача сохраняет игры и творческие программы одновременно.
GPU-render требует дискретную видеокарту независимо от дополнительного флага ИИ.

Реестр `performance-models.json.workloadObservations` разделяет сравнения по
программе, операции и компоненту. Каждый набор имеет ссылку, дату, версию набора,
метрику, направление, базовое значение и точные модели (для GPU также VRAM).
Выбирается один первый подходящий набор, без склейки разных версий/площадок.
Отношение к базовой модели — внутренний относительный показатель, не FPS.
Решение владельца 2026-11-05: для нескольких основных творческих задач среднее
считается по подтверждённым тестам; при неполном покрытии статус `partial`,
`coverage` содержит число измеренных и всех основных задач. Это оценка только
измеренной части, а не прогноз всего сценария. Непроверенные задачи сохраняют
`score: null` и перечисляются в предупреждении по CPU/GPU. Упоминаются только
программы из задач клиента. Полностью неизвестный набор остаётся `not_evaluated`.
Второстепенные
задачи сохраняются для требований и отчёта, без самостоятельного бонуса к рейтингу.
Текущий коэффициент 0.24 приводит относительный показатель к шкале существующей
целевой функции; это политика подбора, не физическая характеристика.

Добавлен контролируемый сравнительный тест семи GPU для Blender от Puget Systems
(2026-06-10), включая R9700 32GB. База RTX 5070 12GB: 5968 баллов = 100%.
Точная версия Blender и драйверов в статье не раскрыта, это записано в метаданных.
Нельзя объединять этот набор с другими обзорами или переносить его на Twinmotion.
Источник: https://www.pugetsystems.com/labs/articles/amd-gpu-rendering-performance-is-radeon-a-viable-alternative/

Источник: https://gamersnexus.net/cpus/amd-ryzen-9-9950x-cpu-review-benchmarks-vs-7950x-9700x-14900k-more

Twinmotion 2024.1.2: AEC Magazine, 11 raster и 9 path-traced результатов для
11 профессиональных GPU. Сцена около 20 GB VRAM, 6/5 изображений 4K соответственно.
Наборы имеют `referenceOnly: true`: не участвуют в подборе, пока профиль не задаёт
режим рендера и размер сцены. Админка показывает «применимость требует уточнения».
Два падения path tracer записаны как failedObservations, не как нулевые баллы.
Источник: https://aecmag.com/workstations/workstations-for-arch-viz/
Копии проверенных графиков: `data/performance-evidence/2026-11-04/`.

Для отсутствующих точных моделей или неприменимых наборов оценки остаются null;
подбор проверяет совместимость и сообщает, что
оптимальность по производительности не подтверждена. Прежняя оценка CPU по числу
ядер удалена. Игровой подбор продолжает использовать свой набор тестов.
Админка показывает отдельные сценарии и пробелы покрытия. Правила общие для
организаций, товары и их предложения по-прежнему разделены по организации.

Остаются отдельными следующими задачами: расширение покрытия новыми измерениями,
контекст Twinmotion (режим и размер проекта),
пересмотр баланса бюджета/весов смешанных задач, оптимизация перебора и очереди
расчётов. Этот этап не устраняет все ранее найденные ограничения конфигуратора.
