# API p1 и локальная загрузка

Контракт основан на ответах Network, предоставленных владельцем, и проверен живой
загрузкой 2026-10-08: 299 страниц, 29 874 товара, столько же уникальных skuOver.
Сохранённый JSON повторно прочитан, полнота подтверждена; данные и секреты исключены
из Git. Стек приложения не выбран; PowerShell — вспомогательный инструмент.

## Авторизация

POST https://p1.overclockers.kz/api/auth/login

JSON: `{"login":"...","password":"..."}`. Ответ — строка токена.
Загрузчик принимает текст или JSON-строку. Передаёт `Authorization: <токен>`
без Bearer. Срок действия и refresh неизвестны. Каждый запуск получает новый токен.
При ошибке, включая 401/403, останавливается; старый готовый каталог не заменяется.
Токен не записывается на диск. Тела ошибочных ответов не выводятся.

## Каталог

POST https://p1.overclockers.kz/api/master-catalog/all

```json
{"pageSize":100,"pageNumber":0,"sort":{"active":"","direction":""},"filterModels":[]}
```

Страницы с нуля. Размер 100 проверен владельцем в интерфейсе.
Ответ: hasNext, hasPrevious, totalElements, totalPages, currentPage, pageItems.
Загрузка до hasNext=false. Число 29 875 из примера не является постоянным.

Проверки: последовательность страниц, согласованность метаданных, непустые
промежуточные страницы, уникальность строковых skuOver, итоговое количество.
При расхождении нужно повторить загрузку целиком. Старый каталог сохраняется.
API не предоставил snapshot ID; сортировка не задана. Даже эти проверки не
гарантируют состояние всех товаров на один момент времени.

## Хранение и сопоставление

Все поля товаров сохраняются, включая неизвестные, null, архивные товары и
товары без наличия. Для будущих денежных расчётов использовать decimal.
Цены в KZT, пользователю не показываются. Расчёт по priceLoan; priceBonus и
priceSpecial — на будущее. 0/null — цена не рассчитана.

dealersData сохраняется как исходные строки. Первое число в скобках — остаток.
Для отбора наличие означает положительный остаток хотя бы на одном учитываемом
складе. Остатки OVER ALB (склад закрыт) и VENDER_P_S по указанию владельца
исключаются. VENDER_S, VENDER_P и VENDER_G относятся к одной фирме; запросы
свыше 50 шт. требуют отдельного учёта этой группы. VENDER_P_S не суммируется с
ними. Исходные строки и остатки между складами не переписываются.

Города и сроки доставки из файла владельца сохранены в `config/supplier-delivery.json`.
Сроки заданы в рабочих днях; `0` означает доставку в городе склада, `null` —
доставка запрещена или склад не обслуживает направление. В каталоге могут быть
поставщики без города/срока из этой матрицы: для них направление не предполагается.
Смысл трёх чисел после остатка в `dealersData` неизвестен.
code1C может быть null. Единицы guarantee и значения quarantineStatus требуют уточнения.

Сопоставление: точные непустые article + manufacturer с полями «Артикул» +
«Производитель» в характеристиках over-shop.kz. Не использовать внутренний код
у заголовка. Не менять регистр, не применять приблизительное сравнение.
Отсутствие/несколько совпадений — ручная проверка. Пробный поиск и проверка реализованы
в tools/shop_match.py; описание — docs/SHOP_MATCHING.md.

Подтверждённый пример: skuOver 88947637, SRT3000XLI + APC:
https://over-shop.kz/catalog/periferiya/zashchita_pitaniya_i_elementy_pitaniya/istochniki_bespereboynogo_pitaniya/68986/

Повторная загрузка исправила ошибку Windows PowerShell: .Content декодировал
кириллицу неверно при отсутствии charset. Теперь JSON декодируется строго из
RawContentStream как UTF-8. Кириллица в сохранённом файле проверена. Добавлен
регрессионный тест с неверным .Content и правильными исходными байтами.

## Запуск из корня проекта

Заполните login и password в `.secrets/p1.credentials.json` локальным редактором.
В новом клоне, если файла ещё нет:

```powershell
New-Item -ItemType Directory -Force .secrets
Copy-Item config/p1.credentials.example.json .secrets/p1.credentials.json
```

Не перезаписывайте уже заполненный файл шаблоном. Секреты не вводите в командной строке.

```powershell
powershell -NoProfile -File tools/p1-catalog.ps1
```

Результат: `data/p1-catalog.json`, метаданные и массив `items`. Полный проверенный
каталог заменяет предыдущий атомарно. В консоли только прогресс, без цен и токена.
HTTPS redirects запрещены. Повторные запросы и refresh автоматически не выполняются.
`.secrets/` и `data/` исключены из Git. Локальный файл доступа не зашифрован.

Локальный аудит заданных владельцем категорий запускается командой
`python tools/audit_pc_catalog.py`. Скрипт использует только явно заданные 11
категорий; название жёстких дисков сопоставлено с p1 `Жесткие диски 3.5" (для ПК)`.
На снимке от 2026-10-08 найдены все 11 категорий из 483; всего 4 130 товаров.
У всех есть skuOver, article и manufacturer. Ноль считается незаполненной ценой.
Для актуального отбора товар включается только если хотя бы в одной строке
dealersData количество в скобках положительное. Одного непустого dealersData
недостаточно. Для расчёта сборки дополнительно требуется ненулевая priceLoan.
Для доступности аудит исключает остатки поставщиков, перечисленных в политике
`config/supplier-delivery.json`; город и срок доставки берутся оттуда по точной
метке поставщика. Положительный остаток на исключённом складе не делает товар
доступным.

Тесты без подключения к p1:

```powershell
powershell -NoProfile -File tests/p1-catalog.tests.ps1
```

Далее: сопоставление 20 товаров разных категорий, выбор способа обхода магазина
и получение характеристик.
