# Пробное сопоставление p1 и магазина

`tools/shop_match.py` использует только стандартную библиотеку Python 3.
Python найден в комплекте runtime Codex; системная команда python недоступна.
Из корня проекта (для этой машины):

```powershell
$env:PYTHONIOENCODING='utf-8'
& 'C:/Users/dimak/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' tools/shop_match.py
```

На другой машине: `python tools/shop_match.py`. Для тестов: `python tests/test_shop_match.py`.
Только выборка без сети: `python tools/shop_match.py --select-only`.
Повторная проверка отдельных товаров выборки: `python tools/shop_match.py --sku 88959370
--sku 88945675 --sku 88946397` (одной строкой). Результаты такой проверки пишутся
в data/shop-matches-followup.json, исходный pilot и его выборка не перезаписываются.

## Правило

Поиск: `https://over-shop.kz/catalog/?q=<manufacturer article>&type=catalog`.
Оба значения обязательны. Поиск может выдавать похожие и нерелевантные товары.
Из каждого кандидата читаются строки таблицы характеристик `tr.js-prop-replace`
с `js-prop-title` и `js-prop-value`. Если таблицы нет, читается компактный блок
характеристик properties__item с теми же маркерами полей. Не используем название, код у заголовка,
JSON-LD sku, рейтинг или цену для подтверждения совпадения.

Точные непустые `article` и `manufacturer` сравниваются с «Артикул» и
«Производитель». Регистр, знаки, внутренние пробелы и форма Unicode не меняются.
Удаляются только внешние отступы HTML-разметки; HTML entities декодируются.
Повторные противоречащие значения не принимаются. Все извлечённые характеристики
сохраняются как наблюдения магазина, а не независимо проверенные технические факты.

Статусы: matched, mismatch, not_found, ambiguous, needs_review, error.
Пагинация обходится по ссылкам PAGEN_N, с обязательным сохранением исходного запроса.
Лимиты одной проверки товара: 10 поисковых страниц, 250 карточек. Достижение лимита,
повтор одной страницы или ошибка чтения не позволяют подтвердить единственность.
Если обязательное поле отсутствует, фиксируется missing_identity с названием поля;
такая карточка требует проверки. Если другое поле уже явно не совпадает, кандидат
можно отклонить даже при отсутствии второго поля.
Два точных совпадения в разных карточках — ambiguous, ссылка не назначается.
Разные пути одной карточки различаются по числовому ID и не считаются дублями товаров.

## Результат

- data/shop-sample.json — 20 товаров из 20 заданных категорий, без цен.
- data/shop-matches-pilot.json — связь, статусы, значения полей и характеристики кандидатов.
- data/shop-evidence/<UTC>/ — HTML, прочитанный при проверке, для аудита извлечения.

Берётся первый подходящий товар каждой категории в исходном каталоге;
для ИБП — ранее согласованный APC 88947637. Выборка не случайная и не доказывает
долю совпадений всего каталога. Результат matched означает единственную точную
карточку среди кандидатов этого поиска, а не доказанную уникальность во всём магазине.
not_found означает отсутствие кандидатов в данном поиске, а не отсутствие товара.
Выборка и результаты исключены из Git. p1 не изменяется, секреты не используются.

Этот bounded pilot не запускает обход всех 29 тысяч товаров и не имеет расписания.
Для масштабирования ещё нужно проверить полноту поиска или получить индекс магазина.

## Первая проверка, 2026-10-08

20 товаров: 7 matched, 9 mismatch, 3 needs_review, 1 not_found.
Примеры строгого отказа: MaxSun/Maxsun, SL500-512GB/SL500 512GB,
VCNRTXPRO5000-SB OEM/VCNRTXPRO5000-SB. Правило не ослаблялось.
Среди needs_review есть многостраничная поисковая выдача и карточки без
извлечённой таблицы характеристик. Отказы не означают отсутствие товара в магазине.

## Доработка поиска

Пагинация поддерживается; страницы другого запроса/домена не обходятся.
В сохранённом HTML двух неполных карточек отсутствовали Артикул и Производитель:
показаны лишь гарантия и внутренний код. Названия товаров не используются для
восстановления недостающих идентификаторов.
Каждый кандидат теперь содержит identityStatus и identityFields, а результат —
searchPages, searchTraversalComplete и verificationComplete. Полный обход выдачи
сам по себе не означает, что удалось прочитать обязательные поля всех кандидатов.

Повторно проверены три SKU: 88959370 (2 страницы, 26 кандидатов), 88945675
(1 страница, 1 кандидат), 88946397 (10 страниц, 200 кандидатов). Все остались
needs_review, точных совпадений среди прочитанных характеристик нет. На отдельных
карточках не хватает одного или обоих обязательных полей. Внешний поиск по домену
и обеим строкам дал для Ocypus ту же неполную карточку, дополнительных кандидатов
для двух других запросов не вернул. Это не доказывает отсутствие товара в магазине.

Сводный результат с сохранением исходных 17 проверок: data/shop-matches-current.json.
Подтверждено по-прежнему 7 из 20; правила не ослаблялись. 16 локальных тестов проходят.
Независимое review Claude пока недоступно из-за баланса; запрос сохраняется в очереди.

сам по себе не подтверждает связь с p1. Нужно читать карточку и проверять оба поля.
