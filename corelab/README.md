# CoreLab

Рабочее ТЗ: [CORELAB_SPEC.md](CORELAB_SPEC.md). Дополнение этапа 5 «СВОЙСТВА»
и анализ согласованности: [STAGE_05_PROPERTIES.md](docs/STAGE_05_PROPERTIES.md).

Правила характеристик: [описание и API](docs/UNIVERSAL_PROPERTY_RULES.md).
В каталоге выберите категорию → «Структура свойств»: редактор правил,
обязательность, условия, блокировка ИИ и проверка структуры. В карточке товара
можно добавлять и редактировать свойства из структуры назначенных категорий,
указывать состояние значения и его источник. Сохранение сбрасывает предыдущий
`validity_check`, чтобы товар был проверен заново; автоматическая перепроверка
появится на этапе 7.
Платная загрузка характеристик и генерация структуры категории удалены.
Структуру можно редактировать вручную или применять локальный шаблон;
характеристики — редактировать вручную и импортировать из подтверждённых локальных данных.
Настройки API-ключей сохранены для диалога и подбора ПК.
Результаты проверки: [этап 5](docs/test-reports/STAGE_05.md),
[этап 6](docs/test-reports/STAGE_06.md).

Локальная закрытая админ-система. Для запуска нужен Docker Desktop.

Приложение подбора ПК: `http://localhost:5173/mini-app/`. Товары, текущие цены,
остатки, допуск и технические характеристики для каждого расчёта приходят из CoreLab.
Локально остаются только правила доставки; старые файлы снимка p1 и характеристик
к контейнеру приложения не подключены. При отсутствии допуска или связи с каталогом
приложение не выдаёт сборку. Отдельный экран каталога: `http://localhost:5173/catalog-preview/`. Войдите
администратором по тому же адресу `localhost:5173`; экран откроет защищённый
предпросмотр без Telegram. Ссылка также есть в «Настройки → Mini App».
Для покупательского входа нужны Telegram Web App `initData` и серверная настройка
`TELEGRAM_BOTS_JSON`. Контракт и границы описаны в
[`docs/MINI_APP_API.md`](docs/MINI_APP_API.md).

1. Скопируйте `.env.example` в `.env` и задайте собственные `POSTGRES_PASSWORD`, `SESSION_SECRET`, `ADMIN_USERNAME` и `ADMIN_PASSWORD`. Используйте стойкий пароль администратора.
2. Обновите пароль в `DATABASE_URL`, чтобы он совпадал с `POSTGRES_PASSWORD`.
3. Из каталога `corelab/` выполните `docker compose up -d --build`.
4. Откройте `http://localhost:5173/admin/login`. API: `http://localhost:8000/docs`.

Данные PostgreSQL сохраняются в именованном Docker volume `corelab_postgres_data`. Сервисы слушают только loopback. Команда остановки `docker compose down` сохраняет данные; `docker compose down -v` удаляет том с данными.

Раздел «Каталог» (`/admin/catalog`) показывает локальные товары CoreLab, дерево категорий, цены связанных актуальных предложений и характеристики. Категории можно независимо включать в подбор; изменения записываются в журнал аудита. Карточка товара поддерживает редактирование и добавление свойств из категорий с валидацией типа, источника и состояния значения. Раздел «Источники» (`/admin/sources`) показывает исходные данные предложений p1. Снимок и порядок его загрузки описаны в `docs/P1_IMPORT.md`; импорт не запускается автоматически. Автоматическая перепроверка товара и отдельная вкладка журнала относятся к следующим этапам.

Защита сессий и расходов ИИ (2026-11-12): административные токены проверяются
по серверной записи в `admin_sessions`. Выход отзывает текущий токен;
смена или сброс пароля делает недействительными все старые токены пользователя.
После смены своего пароля браузер получает новую сессию и CSRF-cookie.
При переходе на миграцию `0032_session_ai_limits` старые сессии требуют повторного входа.

Общий лимит ИИ организации хранится в PostgreSQL и применяется к диалогу,
планировщику и объяснениям независимо от провайдера и клиентского сеанса.
Переменные backend: `AI_REQUESTS_PER_MINUTE=30`, `AI_REQUESTS_PER_DAY=500`,
`AI_MAX_CONCURRENT=2`. Суточное окно — UTC. Неуспешные попытки также считаются;
это лимит числа обращений, а не суммы в валюте. При недоступности БД вызов
платного провайдера не выполняется. Осиротевшая блокировка параллельного вызова
истекает через 10 минут; смена провайдера и перезапуск не сбрасывают счётчики.

Mini App дополнительно ограничивает адрес клиента: 12 запросов в минуту,
120 в час и 5 новых диалогов в час. Адрес передаётся frontend-прокси с HMAC,
для которого в `.env` нужен отдельный случайный `MINI_APP_PROXY_SECRET` (32 байта).
Ключ не должен иметь префикс `VITE_`. Пользовательские заголовки адреса и подписи
прокси перезаписывает; неподписанным forwarded-заголовкам Mini App не доверяет.
Источник адреса — сетевое соединение frontend; пользователи за одним NAT/туннелем
могут делить клиентский лимит. При добавлении внешнего прокси следует отдельно
настроить проверенную цепочку доверия, не доверяя произвольному X-Forwarded-For.
Ответ ограничения — HTTP 429 с `Retry-After`.
