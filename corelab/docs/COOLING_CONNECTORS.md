# Подключение охлаждения CPU и подсветки

В категориях плат, кулеров и СЖО подключения хранятся JSON-массивами.
Существующее `motherboard_fan_headers` расширено на CPU_FAN, CPU_OPT,
SYS_FAN/CHA_FAN и помпу. Для совмещённого разъёма используется одна запись
с несколькими `roles`, а не несколько независимых разъёмов.

Общие для воздушных кулеров и СЖО свойства: `cooler_fan_connectors` и
`cooling_lighting_connectors`. Для СЖО добавлено `aio_pump_connectors`, для
плат — `motherboard_lighting_headers`. Новые обязательные свойства не
заполняются предположениями. Старые значения SYS_FAN не подтверждают CPU_FAN.

Запись содержит `kind`, `count`, каноническое `raw`; для разъёмов платы —
`roles`, подтверждённые `pins`, `control`, `max_current_a`, для двигателя —
`current_a`. Одинаковые обозначения и повторные записи нормализуются;
конфликтующие количества и типы отклоняются. Опубликованные обозначения
физических разъёмов сохраняются в `header_ids`; один разъём нельзя указать
сразу в нескольких группах.
Ссылки на первоисточники остаются в записи характеристики товара.

Количество подключений кулера/СЖО означает число внешних подключений в
подтверждённой комплектной схеме, а не количество вентиляторов. Для
разветвителя нужен суммарный ток подключённых устройств. Неизвестные общие
кабели, контроллеры, SATA/Molex/USB требуют проверки схемы подключения.

Сборщик распределяет вентиляторы CPU, помпу и добавленные корпусные
вентиляторы по физическим разъёмам платы без повторного использования.
Проверяются назначение, число пинов, режим PWM/DC и токовая нагрузка.
Недостающие сведения дают «Требуется проверка», доказанная нехватка или
несовместимость исключает комбинацию.

ARGB (`argb_3pin_5v`) и RGB (`rgb_4pin_12v`) учитываются отдельно по типу и
количеству подключений кулера/СЖО и добавленных корпусных вентиляторов.
Неподтверждённая подсветка или нехватка её разъёмов выводится предупреждением,
не отменяя подтверждённую работу охлаждения. Проверка подсветки пока не
моделирует лимит числа светодиодов или питание внешнего контроллера.
Штатные вентиляторы корпуса не имеют отдельного подтверждённого перечня
подключений в текущей структуре; их цепи питания здесь не сертифицируются.

Применение структуры: `python /opt/corelab-tools/sync_cooling_connector_rules.py`
(предпросмотр), затем та же команда с `--apply`. Скрипт использует существующие
коды и связи, сохраняет источники, нормализует прежние записи и пересчитывает
допуск. Повторный запуск не создаёт правил или значений повторно.

## Дозаполнение исключённых товаров

`recover_cooling_properties.py --audit-id <id>` восстанавливает точный список товаров,
потерявших допуск в транзакции добавления полей. Флаг `--apply` создаёт штатные
задания `property_load` пакетами до пяти товаров; `--work --workers 3` выполняет
конечный проход обычного загрузчика. `--remaining` выбирает ещё не допущенные товары,
`--products <id> ...` ограничивает запуск исходным списком из аудита.

Режим `fill_missing_codes` разрешает дозаполнение только свойств подключений,
сохраняет известные значения других свойств и повторно проверяет состояние карточки
после исследования. Конкурирующая ручная правка отменяет запись результатов.
Существующий перечень разъёмов платы допускает обогащение, только если новое
подтверждение не противоречит прежнему количеству разъёмов каждого назначения;
предыдущие значения и ссылка сохраняются в аудите. Обычная загрузка пустых карточек
сохраняет прежнее поведение. Используется активный провайдер из настроек CoreLab.
