# Mini App: каталог и контекст организации, API v1

Экран каталога доступен локально по `/catalog-preview/`. В браузере откройте
`http://localhost:5173/catalog-preview/` после входа администратора на `localhost:5173`:
экран получит отдельный токен предпросмотра через CSRF-защищённый API. Ссылка есть
также в «Настройки → Mini App». Без админ-сессии экран показывает ссылку для входа.
В Telegram Web App он проверяет `initData` на сервере, позволяет выбрать магазин,
искать и листать допущенные товары и открывать карточку по стабильному ID.
Клиент подключения находится в `mini-app/catalog-client.mjs`; он хранит в памяти только текущую сессию и ответы API,
а в браузерном хранилище — только идентификатор последнего выбранного магазина.
Собственная база товаров и методы изменения каталога отсутствуют.

## Выбор магазина

1. Проверенный `start_param` рекламной ссылки имеет приоритет над последним магазином.
2. Собственный бот организации закреплён за ней на сервере; перейти к другой организации
   с его сессией нельзя.
3. В общем боте при входе без ссылки используется последний выбранный доступный магазин.
4. При первом входе возвращается сессия выбора магазина без доступа к товарам.
5. Неверная/недоступная ссылка общего бота возвращает `organization: null` и
   `launch_error: invalid_shop_link | shop_unavailable`; интерфейс должен показать сообщение
   и выбор магазинов. Другой магазин автоматически не подставляется.

Формат ссылки: `https://t.me/<bot>/<app>?startapp=shop_1`.
Метка кампании: `shop_1_c_summer_2026`. Она сохраняется в контексте сессии и журнале
`mini_app.launch`, без хранения Telegram-профиля. При ручной смене магазина метка очищается.
Это учёт запусков, а не система рекламной аналитики или атрибуции заказов.

## Авторизация

`POST /api/v1/mini-app/session` принимает `bot`, исходную строку `init_data` из
`Telegram.WebApp.initData`, необязательный `remembered_organization_id`.
Сервер проверяет HMAC SHA-256, уникальность полей, Telegram user ID и время
`auth_date` (не старше 5 минут, не из будущего). Непроверенные данные
`initDataUnsafe` и `tgWebAppStartParam` не являются авторизацией.

Ответ: `access_token`, `token_type: bearer`, `expires_in: 3600`, `organization`,
`campaign`, `launch_error`. Токен подписан отдельной солью, содержит контекст организации,
ограничен чтением каталога и не принимается в административном API.
Все следующие запросы: `Authorization: Bearer <access_token>`, без admin-cookie.
Ответы имеют `Cache-Control: private, no-store`.

Контракт Telegram проверен по официальной документации:
https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app

## Конфигурация серверных ботов

`TELEGRAM_BOTS_JSON` — секретная переменная окружения сервера. Формат:

```json
{
  "corelab": {"token": "<server-only-token>"},
  "shopbot": {"token": "<another-server-only-token>", "organization_id": 1}
}
```

Имя `bot` выбирает серверную конфигурацию; корректная подпись должна соответствовать
именно её токену. Без `organization_id` бот общий, с ID — закреплён за магазином.
Секреты не помещать в клиент, URL, Git или журналы. После настройки переменной
пересоздать backend. По умолчанию список ботов пуст; реальные Telegram-сессии не выдаются.
Удаление конфигурации бота или смена его привязки блокирует ранее выданную сессию.

В настройках организации главный администратор включает «Магазин доступен в Mini App».
По умолчанию публикация выключена. Выключение немедленно блокирует каталог для
покупательских сессий. Это не создаёт бота и не публикует приложение в Telegram.

## Операции

- `GET /api/v1/mini-app/organizations?page=1&page_size=25` — доступные магазины;
  для собственного бота только его организация.
- `POST /api/v1/mini-app/organization` с `organization_id` — явный выбор и новая сессия.
- `GET /api/v1/mini-app/context` — название, короткое имя, логотип, цвет, кампания.
- `GET /api/v1/categories` — категории с товарами, прошедшими фильтр допуска.
- `GET /api/v1/products` и `/api/v1/selection/products` — одинаковый строгий допуск.
- `GET /api/v1/products/{id}` — карточка по стабильному ID CoreLab; чужая или
  недоступная карточка возвращает 404.

Списки: `page >= 1`, `page_size 1..100`, `total`, `items`; товары поддерживают `q`
и `category_id`, сортируются по стабильному ID. Внешний параметр организации
не определяет область выборки: она всегда берётся из подписанной сессии.

Товар выдаётся, только если `validity_check=true`, `selection_enabled=true`,
связанная категория имеет `selection_category=true` и есть хотя бы одно заполненное
техническое свойство в состоянии `known`. Системные поля, пустые строки/массивы/объекты,
`null`, `unknown` и `not_applicable` сами по себе не обеспечивают наличие характеристик.
Один и тот же фильтр применяется к спискам, подбору, карточке и категориям.

Характеристика: `code`, `label`, `value_type`, типизированный JSON `value`, `unit`,
`value_state`. Числа и boolean передаются соответствующими JSON-типами, списки — массивами.
Цена передаётся десятичной строкой, нулевая/отсутствующая — `null`.
Цена товара — минимальная положительная цена актуальных связанных предложений в его валюте,
как в каталоге администратора. Нет актуальных предложений — `price: null`, без старой цены товара.
`offers` содержит только `is_current=true`: ID, источник, цену, валюту, складские строки
`warehouses` и `snapshot_at`. Произвольный `raw_data` источника не передаётся.
Один ответ (количество, товары, характеристики и цены) читается в read-only транзакции
REPEATABLE READ. Между отдельными запросами страниц каталог может обновиться.

OpenAPI: `/openapi.json`, Swagger: `/docs`. Ответы описаны отдельными Pydantic-моделями.
Каталожные маршруты разрешают только GET, сессии — только контекст доступа.

## Локальная проверка до создания бота

Настройки → Mini App → «Товары для Mini App» или «Открыть каталог Mini App в браузере».
Администратор получает отдельный
часовой preview-токен для своей организации через CSRF-защищённый
`POST /api/v1/admin/mini-app/preview`. Предпросмотр работает и при выключенной
публикации, но не разрешает менять организацию или редактировать товары.

## Подключение существующего интерфейса

```javascript
import { createCatalogClient } from './catalog-client.mjs';
const catalog = createCatalogClient({ baseUrl: CORELAB_API_URL, storage: localStorage });
const launch = await catalog.launch({
  botAlias: 'corelab',
  initData: window.Telegram.WebApp.initData,
});
// Если launch.organization === null — показать выбор через catalog.shops().
// При launch.launchError сначала показать сообщение о недоступной ссылке.
// После явного выбора: await catalog.chooseShop(organizationId).
const page = await catalog.selectionProducts({ page: 1, page_size: 100 });
```

В интерфейсе применять `short_name || 'CoreLab'` и `logo_url || штатный логотип`
независимо друг от друга; основной цвет брать из контекста. При смене магазина очистить
диалог и текущую сборку. Экран каталога очищает список и карточку; клиент отбрасывает
ответы запросов, начатых до смены магазина, и после неудачного переключения больше не
использует прежний токен.

Диалог в `../app/` доступен по `/mini-app/`. Его алгоритм сборки получает из CoreLab
допущенные товары, технические характеристики и текущие предложения через
внутренний read-only API; локально остаются только правила доставки. Экран
`/catalog-preview/` показывает каталог CoreLab через потребительский API.
Telegram-бот на момент этапа не создан. Публикация и проверка настоящего Telegram-запуска
не выполнялись; токен бота для автотестов не нужен.
