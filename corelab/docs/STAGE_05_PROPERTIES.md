# Этап 5: структура свойств категории

Актуальная редакция требований владельца от 2026-10-17. Проверяется структура каталога и ограниченный список из десяти выбранных полей GMC. Остальные требования GMC не применяются.

## Сценарий

1. Выбрать категорию.
2. Изучить 2–5 точных моделей на официальных сайтах производителей.
3. Предложить структуру только по подтверждённым характеристикам: тип, единица,
   допустимые значения, уровень заполнения, условия и основание.
4. Сохранить свойства до заполнения карточек; CRUD и блокировки ИИ доступны
   администратору.
5. Проверить внутреннюю структуру категории кнопкой «Проверить структуру свойств».
   Кнопка загрузки остаётся выключенной до готовности загрузчика и проверок этапа 8.

Уровни: обязательно, условно обязательно, рекомендуется, необязательно. Статус
заполнения является внутренним правилом каталога/подбора. Для условного уровня
хранится ограниченное условие; неизвестные факты не угадываются. Значения `false`,
`unknown`, `not_applicable` имеют разную семантику.

## Структура и сохранность

Свойства категорий используют существующие `attributes` и `category_attributes`;
правила и версии проверок хранятся в `property_rules` и
`category_structure_checks`. Новые категории настраиваются данными, без
изменения программного кода. Совпадающий код переиспользуется при совместимых типе,
единице и нормализации; несовместимое изменение отклоняется. Правило можно
архивировать без физического удаления значений и истории.

Блокировка запрещает ИИ заполнять поле. Она не считается доказательством значения
и не отменяет внутреннюю обязательность. Если товар относится к нескольким
категориям, применяются ограничения каждой из них.

## Несоответствие категории при заполнении

До записи проверять точную модель и её тип по официальному источнику. При явном
несоответствии или сомнении не записывать частичные значения; сохранить товар,
категорию, источник, время, причину и статус пропуска/проверки в журнал. Повторить
проверки категории, структуры и блокировок перед атомарной записью.

Сохраняется правило исходного ТЗ: загружать только товары с нулём заполненных
технических свойств. Этап 8 реализует загрузчик; этап 10 — полноценный экран
журнала. События проверок и пропусков необходимо сохранять уже при выполнении
этапа 8.

## Выполнение

- Универсальный редактор, CRUD, уровни обязательности, условия, состояния значений,
  нормализация, блокировки ИИ и проверки структуры/карточки реализованы.
- Для настольной категории «Процессоры» (ID 44) изучены 3 модели и записаны 10
  внутренних рекомендуемых свойств. Серверные процессоры (ID 284) не затронуты.
- Проверка структуры для ID 44 сохранена; исследовательская заметка пока не
  прикрепляется к категории отдельной сущностью в приложении.
- Старые правила GMC архивированы, не удалены физически. Карточки товаров сохранены.
- Загрузчик и проверка соответствия товара категории относятся к этапу 8.
