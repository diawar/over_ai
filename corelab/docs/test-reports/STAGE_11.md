# Этап 11 — API и экран каталога Mini App

Дата: 2026-10-18.

API `/api/v1` отдаёт каталог по подписанной потребительской сессии после проверки
Telegram `initData`. Товар появляется в списке, подборе, карточке и категориях
только при `validity_check=true`, `selection_enabled=true`, участвующей категории
и заполненной технической характеристике. Цена и предложения читаются из актуальных
связанных записей, цена товара не берётся из прежнего поля `products.price`.
Ответы типизированы Pydantic и опубликованы через OpenAPI. Контекст организации
берётся из подписанной сессии, запись товаров через потребительский API отсутствует.

Экран `/catalog-preview/` размещён на том же backend, что и API. Он получает контекст
магазина, категории, список и карточку через `mini-app/catalog-client.mjs`, хранит
в браузере только ID последнего магазина. При смене магазина сбрасывает каталог и
карточку; неудачный переход не оставляет активной прежнюю сессию.
В обычном браузере без Telegram экран получает ограниченный токен предпросмотра
по админ-сессии и CSRF. Удобный адрес — `http://localhost:5173/catalog-preview/`, через
прокси админ-интерфейса, после входа на том же хосте.

Проверки:

- `docker compose run --rm -T backend pytest -q tests/test_mini_app.py tests/test_mini_migration.py` — 22 passed. Включены OpenAPI, доступ, фильтрация, пагинация, цены, изоляция организаций, миграция и выдача статического экрана.
- `node --test mini-app/catalog-client.test.mjs` — 5 passed.
- `npm.cmd run test -- --run src/mini-app-settings.test.tsx` — 1 файл прошёл.
- Браузерные проверки — 3 passed: Telegram Web App, предпросмотр по админ-сессии через порт 5173 и ссылка входа без сессии.
- `npm.cmd run build` — TypeScript и Vite успешны. Локальный `/catalog-preview/` и его скрипт ответили 200.

Проверка реального Telegram-запуска и публикация не выполнялись: бот не создан и
`TELEGRAM_BOTS_JSON` не настроен. Демонстрационный диалог в `../app/` и его локальный
алгоритм сборки не переведены на новый каталог; это отдельная интеграционная задача.
Исходный диалог теперь снова доступен по `http://localhost:5173/mini-app/` через
отдельный сервис `mini_app`.

Исправление 2026-10-19: перед подбором диалог запрашивает у CoreLab текущие
допущенные товары и предложения; локальный снимок p1 больше не используется. Недопущенный
SKU `55398` (Intel Core i5-12400 OEM) исключён. При ошибке проверки выдача сборки
блокируется. Проверки: Node 10/10, backend Mini App 22/22; локальный HTTP-запрос
вернул `no_verified_build`. Это ожидаемо, поскольку в CoreLab пока нет допущенных
блоков питания (540 из 540 с `validity_check=false`).

Переход 2026-10-19: внутренний read-only API CoreLab отдаёт допущенные товарные
записи с действующими связанными предложениями p1. Диалоговый подбор берёт оттуда
названия, цены и остатки при каждом расчёте. Подтверждённые технические
характеристики теперь также приходят из CoreLab; локальны только правила доставки. Монтирование
`data/p1-catalog.json` в сервис `mini_app` удалено; проверка внутри контейнера
подтвердила отсутствие файла. После переключения локальный статус сообщил
`catalogSource=corelab`, 310 допущенных товаров и `builderAvailable=false` из-за
отсутствия допущенных блоков питания. Живой запрос расчёта вернул 422
`no_verified_build`. Проверки: Node 23/23 (включая алгоритм), backend Mini App
22/22, браузерные сценарии 4/4.

Дополнение 2026-10-19: внутренний API отдаёт значения `product_attributes` вместе с
товарами; адаптер подбора формирует проверяемые свойства только из них. Локальный
файл `data/component-characteristics.json` не подключён к контейнеру. При
недостающих полях (например, мощности CPU, подтверждённых габаритах платы и
заводских вентиляторах корпуса) вариант отклоняется. Проверки: Node 23/23,
backend Mini App 22/22; контейнер не видит ни файл p1, ни файл характеристик.
