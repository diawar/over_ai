# Этап 10 — журнал

Дата: 2026-10-18

## Реализация

- `/admin/logs` показывает сохранённые события аудита, задания загрузки свойств с прогрессом и историю импортов.
- События имеют серверную пагинацию и фильтры типа, статуса, диапазона дат, ID товара и действия/ID. Задания и импорты листаются отдельно.
- Журнал показывает автора персонального действия по сохранённому `user_id`. Для фоновой загрузки показывает «Система» и администратора, запустившего задание; для старых записей без достоверного автора — «Не указан». Импорт снимка выполняется системным процессом.
- Товарные и категорийные события ведут к соответствующим карточкам. Секреты, произвольные тексты ошибок, URL и содержимое `details` не возвращаются из API журнала; причины пропуска загрузки допускаются только из фиксированного списка.
- Данные читаются из PostgreSQL `audit_logs`, `jobs`, `job_items`, `import_logs` и сохраняются после перезапуска сервера. Новая миграция не требуется.
