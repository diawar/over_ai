# Этап 8 — пробная ИИ-загрузка свойств товаров

Добавлена загрузка технических свойств из интерфейса структуры категории и карточки товара. Категория допускается только после актуальной проверки структуры; заблокированные для ИИ свойства исключаются. Один запуск категории ограничен пятью пустыми карточками. Фоновое задание сохраняет ход и результат в БД; после перезагрузки страницы статус восстанавливается.

Работник проверяет категорию, артикул и производителя, отсутствие сохранённых технических свойств, актуальность структуры и блокировки до исследования и повторно перед записью. Исследование использует веб-поиск OpenAI и принимает только цитированные HTTPS-ссылки, соответствующие домену производителя. Производитель и модель должны точно совпадать с карточкой. Неоднозначность, отсутствие значений и неверная категория приводят к пропуску без записи. Все нормализованные значения сохраняются одной транзакцией с URL и временем проверки. Помимо технических свойств могут сохраняться выбранные общие поля: описание, дополнительные изображения, гарантия и размеры/вес при наличии подтверждения; основное изображение записывается в поле товара, когда оно пусто. Описание без готового текста производителя ИИ может составить из подтверждённых технических фактов, до 500 символов. Код производителя сверяется с артикулом; состояние и гарантия используют действующие значения по умолчанию, если источник не дал иных подтверждённых сведений. Причина пропуска или ошибки видна в задании и разделе «Журнал». Временные ошибки соединения повторяются максимум три раза; ошибка лимита или баланса не повторяется автоматически.

Повторно использованы существующие таблицы `jobs`/`job_items`, нормализация правил каталога, проверка структуры и блокировка транзакции ручного редактирования. Новая миграция не требуется. Этап не запускает массовое наполнение каталога.

Проверки: 66 backend-тестов, 22 frontend-теста и production-сборка frontend. Тесты загрузчика используют подменённые ответы поиска/API; проверены точная модель, официальный источник, несовпадение категории, отсутствие данных, пустая/заполненная карточка, конкурентное ручное изменение, атомарность, повторная попытка, блокировка, выбранные общие поля и запись в журнал. Контейнеры backend, frontend и DB локально здоровы.

Реальная загрузка через OpenAI не запускалась: ранее аккаунт вернул ограничение по балансу. Для проверки на живых товарах потребуется доступный лимит API. Сохранение найденных фактов в тестах проверено с подменённым ответом провайдера.
